The Personal Data Report gives the data subject a copy of their personal data, extracted from the documents that hold it. The app builds it from your decisions, into your organisation's Word template: first the subject's identifiers, then every extract, each piece of data once, oldest first.

1. Clear what's left

Open Report in the top bar. Left to process lists everything that keeps the report a DRAFT, grouped by what to do, each with a button to do it:

GroupWhat to do
Not reviewed yetWork through these in the Personal Data Reviewer.
Finish in the Personal Data ReviewerFiles with paragraphs still undecided. Confirm N repeat(s) or Decide N opens them.
Held out: conflictsText extracted in one place and left out in another. Settle it in Conflicts.
Choose the passagesItems decided in an old workbook without saying which passages: work through them in the Personal Data Reviewer.
Complete the template[placeholders] left in the template: fill them in the case's template.

A folder that shouldn't count at all (for example exact copies of another folder) can be left out of the report at the bottom of the page, with a reason that is logged.

2. Check the preview

Preview shows the report as it would be built now. Read every extract: is it about the subject, and is anything about someone else still in it? Grey notes under each extract show where it came from; they go in the private register, not the report. To narrow an extract, use Edit in Personal Data Reviewer beside its source, Leave part out there, then ← Report preview to come back.

3. Build

Press Build report. Two read-only files are written to the case's output/personal_data_report/ folder, with their hashes in the audit log:

  • Personal_Data_Report_<case>_<time>.docx: the report for the requester.
  • personal_data_report_register_<case>_<time>.csv: private. Every source of every extract, for the case record. Never send it.

While anything is outstanding, the build is a DRAFT: the file name ends _DRAFT and the first page says so in red. Don't send a draft. Clear what's left and build again.

Always build the report here (or with dsar personal-data-report). Never write it by hand or with another tool: only this build is tied to the decisions, the register and the audit log. Check the data subject's name on the first page before you use it.

4. Finish in Word

Download copy gives you a copy to finish. Tidy the layout if needed, but don't add or change data: change the decision in the Personal Data Reviewer and build again instead. Save the final copy as PDF with the other release documents.
