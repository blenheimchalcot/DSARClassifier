Everything runs on your own machine. The app is reachable only from this computer, nothing is loaded from the internet, and case data never goes into the code folder, OneDrive or git.

Install or update

You need Python 3.10 or later and access to the DSARClassifier repository. In the project folder:

git checkout main
git pull
python3 -m venv .venv          # first time only
source .venv/bin/activate
pip install -r requirements.lock && pip install -e . --no-deps
python -m pytest -q            # every test should pass

Setting up a new machine from scratch: docs/DEPLOYMENT.md.

Point it at the case

Copy .env.example to .env and set:

SettingWhat it is
DSAR_DATA_DIRThe case's data folder (<CASE-REF>/data). Keep it outside OneDrive, Dropbox and iCloud.
DSAR_OPERATORYour name, as the audit log should record it.
DSAR_TEMPLATES_DIROptional: another set of response templates. If unset, Templates/ in the project folder is used: the employee set, including Personal Data Report.docx.
DSAR_CASE_DOCS_ROOTOptional: the folder holding each case's prepared letter and reports, so the case page can check them.
Check the case before every session. DSAR_DATA_DIR decides whose data you are working on. The green banner under the top bar names the data subject: if it isn't the person you expect, stop.

Start the app

dsar serve           # opens the case in DSAR_DATA_DIR
dsar serve --free    # no case: only for trying the tools, nothing is logged

The terminal prints a one-off address. Open it in your browser. Ctrl-C in the terminal stops the app. A restart gives a new address, so close the old tab.

Sign in

Enter your full name. It is recorded with every decision and export you make. Tick Remember my name on this browser to have it filled in next time; you still confirm it, so whoever is at the keyboard is the person recorded.

Switch case

Cases in the top bar lists every case in the cases folder. Opening one is logged in both cases. A case marked legacy was worked before the app kept its own log and needs a tick to open. A case marked chain problems has an audit log that fails its check: find out why before relying on it.

A request can have a main case and deeper searches under it. You always work from the main case: its Personal Data Reviewer and Report use the search's data directly.
